# Xingyao Power Switcher

[中文说明](README.md)

A lightweight Windows tray utility with no main window. It automatically switches the internal display refresh rate and the Mechrevo performance mode according to whether the laptop is plugged in or running on battery.

> [!IMPORTANT]
> This software has **only been tested on the Mechrevo Xingyao 14 2026 Ultra with an Intel Core Ultra X7 358H processor**. Other models, processor variants, and Control Center versions have not been verified. Being able to launch the program does not imply compatibility.

## Project Scope and Required Dependency

This project is not a replacement for Mechrevo Control Center and does not attempt to reimplement it. Its sole purpose is to add automatic refresh-rate and performance-mode switching based on AC or battery power, a feature that the original Control Center currently lacks.

Full functionality requires the original Mechrevo Control Center supplied for the supported laptop to be installed. The Control Center window and its UWP front end do not need to stay open. However, the `GCUBridge` background service installed with Control Center must be running for this utility to read and change Office, Balanced, and Performance modes.

Refresh-rate switching uses Windows display APIs. Refresh-rate switching and basic tray functions may still work without Control Center, but that is not the complete supported configuration and performance-mode functions will be unavailable.

## Features

- Applies separate configurations automatically for AC and battery power.
- Selects 60 Hz or 120 Hz independently for AC and battery profiles.
- Selects Office, Balanced, or Performance mode independently for each profile.
- Shows the current power source, refresh rate, and performance mode in both the tray menu and icon tooltip.
- Optional per-user startup at sign-in.
- No main window, installer, or additional files required at runtime.
- High-DPI support.

Default profiles:

- AC power: 120 Hz + Performance mode
- Battery: 60 Hz + Office mode

## Runtime Design and Resource Usage

- Windows power events report power-source changes; there is no polling.
- Windows display-setting events report refresh-rate changes; there is no polling.
- Performance-mode status is pushed through the local MQTT channel provided by the original Control Center.
- The MQTT connection uses no heartbeat timer. Reconnection uses a backoff timer only while disconnected.
- There is no dedicated permanent polling thread.

In one idle test on the supported laptop, the process accumulated 0 ms of CPU time over 10 seconds, used approximately 25 MB of private memory, and showed stable memory, thread, and handle counts. Results may vary between Windows environments.

## Usage

1. Create a dedicated folder that you intend to keep, for example `D:\Apps\XingyaoPowerSwitcher`. Do not use a browser download folder or temporary directory as the permanent location.
2. Put `XingyaoPowerSwitcher.exe` in that folder. Confirm its location before the first run and before enabling startup.
3. Install the original Mechrevo Control Center for the laptop and confirm that it can change performance modes correctly.
4. Run `XingyaoPowerSwitcher.exe`.
5. Right-click the tray icon and configure AC and battery profiles.
6. Enable “Start with Windows” if desired.

The program uses a single-instance mechanism. Launching it again will not create a second tray instance. Avoid keeping and alternating between copies in multiple folders.

## Configuration Storage

User settings are stored at:

```text
HKEY_CURRENT_USER\Software\MechrevoPowerSwitcher
```

When startup is enabled, a value is added only under the current user at:

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

The startup path is not hard-coded to the developer's computer. The program obtains the full absolute path of its current executable and writes that path to the startup entry. Disabling startup removes the entry and related legacy records.

If you move the EXE after enabling startup, manually launch it once from the new location. When it detects the existing startup entry, it migrates that entry to the executable's current real path. Choosing a permanent folder before the first run is still recommended to avoid confusion between multiple copies and stale paths.
